# django-project — مجموعه پروژه‌های Django

> **نکته درباره ساختار این ریپو:** این ریپو در حال حاضر شامل چند پروژه‌ی *مستقل* Django است که کنار هم قرار گرفته‌اند (هرکدام `manage.py` و تنظیمات خودشون رو دارن). این ساختار برای یادگیری مناسبه، ولی برای نمایش به کارفرما بهتره هر پروژه یک ریپوی جداگانه باشه (پیشنهاد کامل در پایین این فایل).

## پروژه‌های داخل این ریپو

### 🏪 [`myapp/`](./myapp) — پلتفرم دایرکتوری کافه + فروشگاه (پروژه اصلی)
جدی‌ترین و کامل‌ترین پروژه‌ی این مجموعه. یک پلتفرم چندبخشی شامل معرفی و جست‌وجوی کافه‌ها بر اساس شهر، بلاگ، فروشگاه با سبد خرید، سیستم امتیازدهی و کامنت. جزئیات کامل در [myapp/README.md](./myapp/README.md).

### 💬 [`ChatApp/`](./ChatApp) — چت بلادرنگ
اپلیکیشن چت گروهی با Django Channels و WebSocket. جزئیات در [ChatApp/README.md](./ChatApp/README.md).

### 🔐 [`Authentication/`](./Authentication) — سیستم احراز هویت
پیاده‌سازی ثبت‌نام، ورود و پروفایل کاربر با فرم‌های سفارشی Django. جزئیات در [Authentication/README.md](./Authentication/README.md).

### 📁 پوشه‌های ناقص/آزمایشی
پوشه‌های `Chat/`، `sabzsocial/` و `twiliotutorial/` فقط شامل فایل‌های پیکربندی IDE یا یکی‌دو فایل migration هستن و کد قابل‌نمایشی ندارن. پیشنهاد می‌شه این‌ها از ریپو حذف بشن (یا اگه پروژه کامل دارید، فایل‌های واقعی‌شون هم اضافه بشه).

## ⚠️ پیشنهاد جدی: تفکیک این ریپو

نگه‌داشتن چند پروژه‌ی بی‌ربط توی یک ریپو باعث می‌شه کارفرما نتونه به‌سرعت بفهمه هر پروژه چیه و چقدر جدیه. پیشنهاد می‌کنم:

1. `myapp` رو به یک ریپوی جدید مستقل ببرید (مثلاً `cafe-directory-platform`) — چون بهترین نمونه‌کارتونه.
2. `ChatApp` و `Authentication` رو هم می‌تونید جدا کنید یا به همین شکل توی یک ریپوی «تمرین‌ها» نگه دارید.
3. پوشه‌های خالی/ناقص (`Chat`, `sabzsocial`, `twiliotutorial`) رو حذف کنید.

راهنمای گام‌به‌گام دستورات گیت برای این کار توی فایل `INSTRUCTIONS.md` (که جدا براتون فرستادم) هست.

این ریپو الان حدود ۲۶۱ مگابایته که غیرعادی بزرگه، چون فایل‌های زیر مستقیم داخل گیت کامیت شدن:
